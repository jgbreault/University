# Prototype Pipeline 6

Pipeline 6 adds a recall-efficient front end to the Pipeline 5 visual rule extractor. It is designed for testing the same extraction approach on short targeted PDFs and long city-wide zoning bylaws without sending every page to Gemini.

## Design

```text
PDF
 |
 v
01  Local coarse block extraction and scoring
    PyMuPDF text only; no API call
    target-term anchors + nearby blocks + line context
    -> local_blocks_scored.jsonl
    -> candidate_windows.jsonl
 |
 v
02  Gemini context-window refinement
    Small text windows only
    relevance assessment + faithful fine splitting + table/layout routing
    -> refined_windows.jsonl
    -> accepted_windows.jsonl
 |
 v
03  Selected-page visual block extraction
    Gemini sees only accepted pages plus adjacent-page protection
    clause-style text -> hierarchical text blocks
    regulatory tables -> title-inclusive image crops
 |
 +------------------------------+
 v text blocks                  v table images
04  Gemini 3.1 Pro atomic rule extraction
 |
 v
05  Deterministic merge audit and Gemini review
    semantic deduplication + qualifier cleanup
 |
 v
    final_rule_registry.json
```

The first API call is delayed until after local recall. Surrey is the key stress case: its source PDF has 348 pages, compared with 22 pages for Vancouver and 7 pages for Burnaby.

## Local Recall Baseline

These figures are generated locally before Gemini window refinement:

| City | PDF pages | Local blocks | Target-anchor blocks | Candidate windows sent to refinement | Pre-refinement visual pages | Visual-page reduction |
|---|---:|---:|---:|---:|---:|---:|
| Vancouver | 22 | 387 | 15 | 6 | 10 | 54.5% |
| Surrey R1 + shared regulations | 348 | 2,483 | 18 | 14 | 31 | 91.1% |

The final visual-page count should be lower after Gemini rejects irrelevant keyword collisions and context-only windows. These baseline counts measure API-load reduction, not extraction accuracy.

## Run

Open [pipeline6_rule_extraction.ipynb](pipeline6_rule_extraction.ipynb). The notebook is the single public entry point.

1. Set `TARGET_CITY` to `"vancouver"` or `"surrey"`.
2. Keep `LOCAL_ONLY = True` for an API-free recall check.
3. Set `GEMINI_API_KEY` and change `LOCAL_ONLY = False` to run the complete chain.
4. Use `OVERWRITE_API_CACHE = False` to reuse completed Gemini calls.

Surrey defaults to the `R1` chapter plus shared city-wide regulations. Set `INCLUDE_OTHER_ZONES = True` only when intentionally scanning other Surrey residential zones too.

The notebook is generated by `gen_pipeline6_notebook.py`.

## Outputs

```text
outputs/<city>/
  01_local_selection/
    local_blocks_scored.jsonl
    candidate_windows.jsonl
    summary.json
  02_window_refinement/
    refined_windows.jsonl
    accepted_windows.jsonl
    summary.json
  03_visual_blocks/
    text_blocks.jsonl
    table_regions.jsonl
    table_images/
  04_rule_extraction/
    final_rule_registry.json
```

Pipeline 6 reuses Pipeline 5's visual splitter, rule extractor, and merge reviewer. The new code is concentrated in the local selector, the small-window Gemini refiner, and the staged runner.
