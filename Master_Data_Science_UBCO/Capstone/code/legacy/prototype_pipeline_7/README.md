# Prototype Pipeline 7

Pipeline 7 is **Pipeline 5 with safe, quality-neutral token savings**. It reuses
Pipeline 5's three stages unchanged (visual splitter → rule extractor → merge
reviewer) and only changes how images are produced.

## What it optimizes (and why it's safe)

Image tokens dominate Pipeline 5's API cost (every page is rendered and sent for
layout; each table is re-imaged as a crop). Text rule extraction is already
text-only. Pipeline 7 targets only the image side, never the table *reading* that
drives quality.

| # | Optimization | Why quality is unaffected |
|---|---|---|
| **S1** | Page **layout image** rendered at `LAYOUT_SCALE = 2.0`; **table crops** stay at `CROP_SCALE = 3.0` | Table values are read from the high-res crop. The page image is only used to locate tables + transcribe body clause text; 2.0× (≈144 DPI) is lossless for **digital** bylaw PDFs. ~50% fewer tokens on the per-page layout call. |
| **S2** | Skip the layout API call for pages with **no text and no images** | Empty pages cannot produce rules. |
| **S3** | Response caching (`OVERWRITE_API_CACHE = False`) | Re-runs never re-call the API. |

### Deliberately NOT done (deferred — real savings but quality risk)
- Downgrading the layout / merge-review model to a Flash tier.
- Using PyMuPDF's text layer instead of vision transcription for clauses.
- Cutting layout DPI below 2.0.

## Implementation note
The two new knobs (`layout_scale`, `skip_empty_pages`) were added to the shared
`prototype_pipeline_5/gemini_visual_block_extractor.py` in a **backward-compatible**
way: `layout_scale` defaults to `scale`, and `skip_empty_pages` defaults to `False`,
so Pipeline 5 and Pipeline 6 behavior is unchanged. Pipeline 7 simply opts in.

## Run
Open [pipeline7_rule_extraction.ipynb](pipeline7_rule_extraction.ipynb):
1. Set `GEMINI_API_KEY` (the notebook prompts via `getpass` if unset — the key is
   never written into the notebook).
2. Adjust `PDF_PATH` / `PAGES` if needed (defaults to the Burnaby R1 PDF, all pages).
3. Run all cells.

CLI equivalent:
```
python pipeline7_runner.py --pdf <pdf> --pages 1-7 --layout-scale 2.0 --scale 3.0
```

The notebook is generated by `gen_pipeline7_notebook.py`.

## Outputs
```
outputs/<run_name>/
  03_visual_blocks/   text_blocks.jsonl, table_regions.jsonl, table_images/, summary.json
  04_rule_extraction/ final_rule_registry.json, merged_rules_deduplicated.json, ...
```

## Merge-review benchmark
The shared merge reviewer can score its decisions against a gold fixture. Pass
`--benchmark <gold.json>` to `pipeline7_runner.py`, or grade an existing run's
**cached** decisions without re-calling the API:
```
python pipeline7_benchmark.py            # scores outputs/burnaby cached decisions
```
This reuses pipeline5's `evaluate_against_gold` and writes
`merge_review_benchmark_result.json` + `merge_review_benchmark_checks.csv` into the
run dir.

⚠️ **The pipeline5 Burnaby gold is NOT id-compatible with pipeline7.** Pipeline7's
extraction produces a different merge-review population (different `merged_rule_id`s
and different flagged rules), so only part of the pipeline5 gold transfers:
- `benchmarks/burnaby_merge_review_gold_pipeline7.json` — the **10 human-validated**
  gold items that map to pipeline7 (5 share the same id; 5 were re-keyed to pipeline7's
  ids). These are the only items scored.
- `benchmarks/burnaby_pipeline7_review_coverage.json` — the **8 new** pipeline7 review
  items (Claude-drafted expected answers, `needs_human_confirmation: true`, NOT scored)
  and the **7** pipeline5-gold items absent from pipeline7's review set.

Latest cached-decision score (10 validated items): action 0.90, action+count 0.90,
numeric-endpoint 1.00, full-check 0.90. The single miss is the parking-location rule
(`pipeline5_merged_rule_0095`): gold expects a REPLACE split into rear-of-lot +
infeasible-access alternate; pipeline7 KEPT it whole.
